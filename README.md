# HRV-CODE

用**手機相機**量心率變異度（HRV）的實作。手指蓋住後鏡頭，從影像的紅光變化取出脈搏波（PPG），再算 RMSSD 與 SDNN。

這是 YDIR App 裡 HRV 功能的原始碼，抽出來公開給研習會參加者參考。

---

## ⚠️ 重要聲明

**這不是醫療器材，量出來的數字不能拿來診斷或判斷病情。**

相機 PPG 跟心電圖（ECG）是兩件事：它量的是指腹的血流變化，不是心臟的電訊號。光線、膚色、指腹厚度、按壓力道、手抖，每一項都會影響結果。這份程式的用途是**同一個人在相近條件下的前後比較**，不是絕對值的醫學量測。

---

## 最關鍵的限制：30 fps

這支程式真正困難的地方只有一個 —— **相機一秒只有 30 格，一格就是 33 毫秒。而 RMSSD 本身常常只有 20～50 毫秒。**

也就是說，如果直接用原始取樣點抓心跳的位置，光是「格與格之間」的量化誤差就跟你要量的東西同一個數量級，甚至更大。整條處理鏈有一半的工夫都是在對付這件事：

- **三次樣條內插 ×4**（30 Hz → 120 Hz）：把時間解析度從 33 毫秒細分到 8.3 毫秒
- **拋物線頂點定峰**：用峰值附近三點擬合拋物線，取頂點當真正的峰位，解析度再往下鑽到次取樣點

這兩步不是錦上添花，是這個方法能不能用的分界線。

## 處理流程

```
相機影像（160×120 縮圖）
   └─ 取紅色通道平均值 ────────────────── 原始 PPG 訊號
        │
        ├─ 依時間戳重新等間隔取樣 ──────── 相機 fps 不穩，先補成等間隔
        │
        ├─ 訊號品質（SQI）與晃動把關 ───── 四條規則一起看，爛的直接丟掉
        │
        ├─ smoothness priors 去趨勢 ────── 拿掉呼吸與手移動造成的基線漂移
        │   ＋ 移動平均
        │
        ├─ 4 階 Butterworth 帶通 ───────── 截止頻率跟著當下心跳基頻走，
        │                                  不是寫死的固定頻段
        │
        ├─ 三次樣條內插 ×4（30→120 Hz）── 見上面「30 fps」那一段
        │
        ├─ MSPTD 抓拍 ──────────────────── 多尺度峰值偵測
        │
        ├─ 拋物線頂點定峰 ──────────────── 次取樣點精度
        │
        └─ RR 間期 ─────────────────────── RMSSD / SDNN
                                            └─ 再扣掉殘餘的取樣抖動變異
```

### 訊號品質（SQI）

四條檢查一起看，任何一條爛掉都算訊號不好：

| 檢查 | 在看什麼 |
|---|---|
| 振幅範圍 | 沒把手指蓋上去的時候，max−min 幾乎是 0 |
| 頻域能量集中度 | 心跳那個頻段佔總能量的比例 |
| 自相關係數 | 取 lag≈1 拍；沒手指的時候訊號近乎隨機，自相關拉不起來 |
| 前後半段一致性 | 手在動（移動偽影）會讓前半段跟後半段對不起來 |

品質門檻分成兩道，因為 **BPM 和 HRV 對訊號品質的需求差了一個量級**：BPM 是從頻譜主峰讀的，只要脈動的週期性還在就抓得到；HRV 要的是「每一拍的時間點」，峰值往旁邊偏 20 毫秒就直接反映在 RMSSD 上。

| `HRVHistory.js` | 589 | 歷史紀錄與趨勢 |
| `constants.js` | – | 佔位用（見下方「這份程式不能直接跑」） |

### 校正那一段值得單獨看

`HRVCalibration.js` 只有 182 行，但裡面有四個踩過坑才寫得出來的決定：

1. **記錄的必須是「未校正」的相機原始值。** 存校正後的值會讓迴歸在自己的輸出上再擬合，係數震盪而永遠收斂不到真值。
2. **校正綁在「這台裝置 ＋ 這個人」。** 膚色、指腹厚度、按壓力道差很多，混不同人的資料擬合出來的對誰都不準。
3. **RMSSD / SDNN 不能用線性 `a*x+b`。** 誤差主要來自逐拍計時抖動，屬加性雜訊，要在變異數域擬合：`polar² ≈ a2 * cam² + b2`
4. **留每一筆明細而不只是累加值。** 手動輸入一定會有打錯的時候，只有明細刪得掉、重算得回來。

## 這份程式不能直接跑

這是從一個完整的 App 裡抽出來的**參考程式碼**，不是一個裝了就能用的套件。

`hrv_engine.py` 是自足的（只要 numpy + scipy），可以單獨拿去讀、拿去改、拿去餵你自己的訊號。

但三個 `.js` 檔是 React Native（Expo）元件，會用到原本 App 裡的東西，那些**沒有**放進這個 repo：

- `./SoundTouchable` — 會發出點擊音的 `TouchableOpacity`
- `./AudioManager` — 音效系統（還需要一批 mp3）
- `./constants` — 這裡放了一個**佔位版本**，只留 HRV 用得到的 `API_URL`，而且把網址換成了範例字串

`API_URL` 在原本的 App 裡指向一個 Cloudflare Worker，只用來上傳／讀取校正對照資料。**沒有它也能量測**，只是校正功能不會動。
